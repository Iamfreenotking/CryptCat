# CryptCat 图文保姆级教程

本教程只讲 Web 网页端的实际操作。文件和密码在设备本地处理，正常加密和解密不需要登录或联网。

## 一、加密文件

### 第 1 步：打开网页并选择文件

先打开网页，再点击“选择文件”。从系统文件选择器中选择图片、视频、音频、PDF、TXT、ZIP 等文件。选择成功后，页面会显示文件名和大小。

![第 1 步：选择文件](images/web-step-1-select-file.png)

### 第 2 步：输入并确认密码

在“加密密码”输入框输入密码，再在“确认密码”输入框重复输入。两次完全一致后，页面显示“密码一致”。如果显示“密码不一致”，请修改后再继续。

![第 2 步：输入并确认密码](images/web-step-2-password.png)

### 第 3 步：点击加密并保存

确认密码一致后，点击“加密并保存”。浏览器会下载或提示保存一个新的 `.cryptcat` 文件。保存完成前不要关闭网页或刷新页面。

![第 3 步：加密并保存](images/web-step-3-encrypt.png)

## 二、解密文件

### 第 4 步：选择加密文件

切换到“解密”，点击“选择加密文件”，选择刚才生成的 `.cryptcat` 文件。旧版 `.crypt3` 文件也可以选择，程序会自动识别格式。

### 第 5 步：输入解密密码

在“解密密码”输入框输入加密时使用的原密码。密码正确时继续下一步；密码错误时页面会提示失败，原文件不会被当作成功解密。

### 第 6 步：点击解密并保存

点击“解密并保存”，选择保存位置。保存完成后，打开还原出的原文件，确认内容正常，再考虑删除原文件或加密文件。

如果密码错误，解密会失败，不会得到可信的原文件。旧版 `.crypt3` 文件会自动识别并使用兼容流程。

## 三、密码和文件安全

- 忘记密码后，CryptCat 无法替你找回文件。
- 在删除原文件前，先确认解密出的文件能正常打开。
- 不要把密码、API key、签名文件或真实私人文件上传到 GitHub issue。
- 不要把 `.crypt3` 或 `.cryptcat` 测试文件放入仓库；仓库的 `.gitignore` 已经默认排除它们。

## 四、本地部署网页端

把仓库的 `www/` 目录内容放到静态网站目录，不需要 PHP、MySQL 或 Gemini key。

本机测试：

```sh
cd www
python3 -m http.server 8080
```

然后打开 `http://127.0.0.1:8080/`。OpenResty 部署时，把 `www/` 作为站点根目录，并通过 HTTPS 提供页面。

## 五、Web 端测试清单

- 断开网络后仍能打开网页。
- 测试图片、PDF、TXT 和 ZIP 等不同文件类型。
- 测试正确密码、错误密码和两次密码不一致。
- 确认新文件扩展名为 `.cryptcat`。
- 确认旧 `.crypt3` 文件仍能自动识别并解密。
- 测试桌面浏览器窗口缩放、刷新和重新打开页面。
